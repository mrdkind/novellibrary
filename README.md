# NovelShelf 📚

**کتاب‌خوان آنلاین ناول و EPUB — رایگان، استاتیک و ساخته‌شده برای مخاطب فارسی‌زبان**

NovelShelf یک سایت کتابخانه آنلاین برای مطالعه Light Novel، Web Novel و کتاب‌های EPUB است که به‌طور کامل روی **GitHub Pages** (رایگان) منتشر می‌شود. هیچ سرور، دیتابیس، حساب کاربری یا هزینه‌ای لازم نیست؛ همه چیز در مرورگر خواننده اجرا می‌شود.

- 📖 کتاب‌خوان EPUB واقعی با دو حالت مطالعه: **صفحه‌بندی‌شده** (شبیه کتاب‌خوان) و **پیمایشی**
- 🧭 نوار ناوبری فصل در **ابتدا و انتهای هر فصل داخل متن**: «فصل قبلی»، «فهرست فصل‌ها» (پاپ‌آپ وسط صفحه با فیلتر جست‌وجو و هایلایت دقیق فصل جاری) و «فصل بعدی» — بدون افتادن روی متن
- 📊 نوار پایین کتاب‌خوان **مختص فصل جاری** است (درصد و پرش درون‌فصلی) و نوار باریک بالایی پیشرفت کل جلد را نشان می‌دهد
- 🇮🇷 رابط کاربری کامل **فارسی و راست‌به‌چپ** + پشتیبانی از کتاب‌های انگلیسی چپ‌به‌راست
- 🖼️ حفظ تصاویر داخل کتاب، تصویر جلد و فهرست مطالب استخراج‌شده از خود EPUB
- 🔖 ذخیره خودکار محل مطالعه، نشانک‌ها، فصل‌های خوانده‌شده و علاقه‌مندی‌ها (فقط در مرورگر کاربر)
- 🔍 جست‌وجو با نرمال‌سازی حروف فارسی (ی/ي، ک/ك، اعراب، نیم‌فاصله و ارقام)
- 🛠️ افزودن کتاب جدید **فقط با آپلود فایل در GitHub** — بدون دست‌زدن به کد
- 🌓 تم تاریک پیش‌فرض + تم روشن + ۸ تم مطالعه + تم سفارشی
- 👋 بخش خوش‌آمد/راهنمای صفحه اصلی فقط **بار اول** برای هر کاربر نمایش داده می‌شود
- 📤 خروجی/ورودی اطلاعات شخصی برای انتقال بین دستگاه‌ها

## ۱. معرفی و فناوری‌ها

### این سایت چه می‌کند؟

- فهرست کتاب‌ها را از پوشه `novels/` مخزن می‌خواند و کتابخانه عمومی می‌سازد.
- هر کتاب صفحه اختصاصی دارد: کاور، خلاصه، ژانر، جلدها و **فهرست فصل‌ها** (که در زمان Build از داخل EPUB استخراج می‌شود).
- با کلیک روی هر فصل، فایل EPUB همان جلد در مرورگر باز و بدون دانلود دستی خوانده می‌شود.
- پیشرفت مطالعه به‌صورت خودکار (با CFI استاندارد EPUB) ذخیره و در مراجعه بعدی بازیابی می‌شود.

### فناوری‌ها

| بخش | انتخاب |
|---|---|
| رابط کاربری | React 18 + TypeScript (strict) |
| ساخت (Build) | Vite 5 |
| کتاب‌خوان | epub.js 0.3.x |
| آیکون‌ها | lucide-react |
| ذخیره‌سازی محلی | IndexedDB (با لایه دسترسی مستقل در `src/storage/`) |
| فونت | وزیرمتن — میزبانی محلی در `public/fonts/` (بدون وابستگی خارجی) |
| اسکریپت‌های کتابخانه | Node.js 20+ با JSZip و fast-xml-parser |
| تست | Vitest |
| انتشار | GitHub Actions + GitHub Pages |

### سیاست خطای کتابخانه

- **خطا** (JSON خراب، فایل مفقود، شناسه تکراری، ساختار EPUB نامعتبر): کتاب از کاتالوگ **حذف** می‌شود تا بقیه سایت سالم بماند، و دستور `npm run validate:library` با کد خروج ۱ کل انتشار را **متوقف** می‌کند تا مشکل را برطرف کنید. پیام خطا در گزارش Actions، شناسه کتاب و علت را به فارسی نشان می‌دهد.
- **هشدار** (فایل بزرگ‌تر از ۲۵MB، نام فایل مشکل‌ساز، فایل بی‌استفاده): فقط گزارش می‌شود و انتشار ادامه می‌یابد.

```
│   ├── build-catalog.mjs          ← ساخت کاتالوگ (در Build خودکار اجرا می‌شود)
│   ├── validate-library.mjs       ← اعتبارسنجی کتابخانه
│   ├── lib/                       ← منطق مشترک (استخراج EPUB، اعتبارسنجی)

├── src/
│   ├── components/                ← کامپوننت‌های رابط کاربری
│   ├── pages/                     ← صفحات (خانه، کتابخانه، جزئیات، …)
│   ├── reader/                    ← کتاب‌خوان EPUB
│   ├── services/                  ← دریافت کاتالوگ، جست‌وجو، مسیرها
│   ├── storage/                   ← لایه IndexedDB و پشتیبان‌گیری
│   ├── hooks/                     ← کانتکست‌ها و هوک‌ها
│   └── styles/                    ← سیستم طراحی (CSS)
├── public/                        ← فونت، favicon، ربات‌ها (catalog.json خودکار ساخته می‌شود)
├── tests/                         ← تست‌ها + فایل‌های آزمون EPUB
├── index.html
├── vite.config.ts
└── package.json
```

**شما برای مدیریت کتابخانه فقط با پوشه `novels/` کار می‌کنید.** تغییر کد لازم نیست.

## ۳. راهنمای اضافه‌کردن ناول جدید

مثال کامل: افزودن کتابی با شناسه `my-novel` — همه مراحل در مرورگر GitHub و بدون برنامه‌نویسی.

> ⚠️ نکته مهم: رابط وب GitHub امکان آپلود مستقیم «پوشه خالی» ندارد. روش زیر با آپلود فایل‌ها در مسیر مقصد، پوشه را به‌صورت خودکار می‌سازد.

### گام ۱ — ساخت فایل info.json (همین کار پوشه را می‌سازد)

1. در صفحه مخزن، دکمه **Add file → Create new file** را بزنید.
2. در کادر نام فایل تایپ کنید: `novels/my-novel/info.json`
   (به‌محض نوشتن `/` پوشه ساخته می‌شود.)
3. محتوای زیر را کپی و مطابق کتاب خودتان ویرایش کنید:

```json
{
  "id": "my-novel",
  "titleOriginal": "Kumo Desu ga, Nani ka?",
  "titleFa": "من یک عنکبوت بودم، پس چه؟",
  "titleAlt": ["So What if I'm a Spider?"],
  "author": "Okina Baba",
  "translator": null,
  "description": "خلاصه داستان اینجا قرار می‌گیرد؛ حداقل بیست نویسه لازم است.",
  "genres": ["فانتزی", "ایسکای"],
  "language": "en",
  "direction": "auto",
  "status": "ongoing",
  "cover": "cover.jpg",
  "year": 2015,
  "license": null,
  "source": null,
  "notes": null,
  "addedAt": "2026-10-15",
  "volumes": [
    { "file": "volume-01.epub", "title": "جلد ۱", "order": 1 }
  ]
}
```

قواعد فیلدها:

| فیلد | اجباری؟ | توضیح |
|---|---|---|
| `id` | ✅ | حروف کوچک انگلیسی/عدد/خط تیره — **باید دقیقاً با نام پوشه یکی باشد** |
| `titleFa` یا `titleOriginal` | ✅ | حداقل یکی لازم است |
| `author` | ✅ | نام نویسنده |
| `description` | ✅ | خلاصه داستان (حداقل ۲۰ نویسه) |
| `genres` | ✅ | آرایه رشته‌ها |
| `language` | ✅ | مثل `fa` یا `en` |
| `status` | ✅ | یکی از `ongoing` / `completed` / `hiatus` |
| `cover` | ✅ | نام فایل کاور در همان پوشه |
| `volumes` | ✅ | آرایه جلدها با `file` (نام فایل EPUB) |
| `direction` | اختیاری | `auto` (پیش‌فرض) / `rtl` / `ltr` |
| `translator`, `titleAlt`, `year`, `license`, `source`, `notes`, `addedAt` | اختیاری | می‌توانید `null` بگذارید یا حذف کنید |
| `order` در هر جلد | اختیاری | ترتیب نمایش؛ اگر نگذارید از ترتیب آرایه استفاده می‌شود |
| `title` در هر جلد | اختیاری | عنوان نمایشی جلد؛ پیش‌فرض «جلد n» |

### گام ۲ — آپلود کاور

1. در صفحه مخزن وارد پوشه `novels/my-novel/` شوید (یا همان ترفند Create new file با مسیر `novels/my-novel/cover.jpg`).
2. **Add file → Upload files** → فایل کاور را بکشید.
3. فرمت‌های مجاز: `jpg`، `jpeg`، `png`، `webp`، `svg`، `avif`. نام فایل باید دقیقاً همان `cover` در info.json باشد.
4. نسبت پیشنهادی کاور ۲:۳ (مثل ۶۰۰×۹۰۰) است. حجم زیر ۲ مگابایت بهتر است.

### گام ۳ — آپلود EPUB

1. در همان پوشه **Add file → Upload files** را بزنید و فایل `volume-01.epub` را آپلود کنید.
2. نام فایل باید دقیقاً همان `file` تعریف‌شده در `volumes` باشد.
3. اگر فایل بزرگ‌تر از ۲۵ مگابایت است، رابط وب GitHub آن را قبول نمی‌کند — [راه‌حل](#۷-عیب‌یابی).

### گام ۴ — ثبت تغییرات (Commit)

1. پایین صفحه، شاخه `main` انتخاب باشد.
2. یک عنوان کوتاه بنویسید (مثلاً «افزودن کتاب my-novel») و **Commit changes** را بزنید.

### گام ۵ — بررسی انتشار خودکار

1. به تب **Actions** بروید؛ یک اجرای «Deploy NovelShelf…» شروع شده است.
2. روی آن کلیک کنید و مراحل را ببینید:
   - `validate:library` → اعتبارسنجی اطلاعات کتاب شما
   - `npm test` → تست‌ها
   - `build` → ساخت کاتالوگ و سایت
3. اگر همه مراحل سبز شد ✅، سایت تا یک دقیقه دیگر به‌روز است.
4. اگر قرمز شد ❌، روی مرحله شکسته کلیک کنید؛ پیام‌های فارسی محل مشکل را می‌گویند (بیشتر: غلط املایی در info.json یا نام فایل ناهمسان).

### گام ۶ — تأیید ظاهر شدن کتاب

سایت را باز کنید و صفحه را با `Ctrl+Shift+R` تازه‌سازی کنید. کتاب باید در خانه و کتابخانه باشد. اگر نبود → [عیب‌یابی](#۷-عیب‌یابی).

### نام‌گذاری فایل‌ها

- برای شناسه پوشه/کتاب فقط از `a-z`، `0-9` و `-` استفاده کنید.
- نام فایل‌های EPUB/کاور حاوی فاصله یا حروف فارسی «کار می‌کند» اما توصیه نمی‌شود؛ بهترین انتخاب: `volume-01.epub`، `cover.jpg`.
- هرگز از `..`، اسلش، یا نام‌های رزرو استفاده نکنید (اعتبارسنج رد می‌کند).

## ۴. راهنمای تغییر کاور و اطلاعات کتاب

1. وارد پوشه کتاب در `novels/<id>/` شوید.
2. **تغییر متن‌ها** (عنوان، خلاصه، ژانر، وضعیت): روی `info.json` کلیک → آیکون مداد ✏️ → ویرایش → Commit changes.
3. **تغییر کاور**: فایل جدید را با همان نام (`cover.jpg`) آپلود کنید تا جایگزین شود؛ یا نام فایل جدید را در `info.json` هم ویرایش کنید. اگر کاور قدیمی استفاده نمی‌شود، با آیکون سطل حذفش کنید (وگرنه هشدار «فایل بی‌استفاده» می‌گیرید).
4. **هشدار**: اگر `id` را تغییر دهید، پیشرفت مطالعه و علاقه‌مندی‌های ذخیره‌شده کاربران به شناسه قبلی گره خورده‌اند و دیگر نمایش داده نمی‌شوند. `id` را دست‌نخورده نگه دارید.

## ۵. راهنمای اضافه‌کردن جلد جدید

1. فایل EPUB جدید را در پوشه کتاب آپلود کنید، مثلاً `volume-02.epub`.
2. `info.json` را ویرایش و جلد را به آرایه `volumes` اضافه کنید:

```json
"volumes": [
  { "file": "volume-01.epub", "title": "جلد ۱", "order": 1 },
  { "file": "volume-02.epub", "title": "جلد ۲ — نبرد نهایی", "order": 2 }
]
```

3. `order`ها را منحصربه‌فرد و صعودی نگه دارید؛ ترتیب نمایش سایت از همین عدد می‌آید.
4. Commit کنید و تب Actions را چک کنید. فهرست فصل‌های جلد جدید به‌صورت خودکار از داخل EPUB استخراج می‌شود.

## ۶. انتشار اولیه روی GitHub Pages

این بخش یک‌بار برای همیشه انجام می‌شود (حدود ۵ دقیقه):

1. **ساخت مخزن**: در GitHub دکمه **New repository** → نام (مثلاً `novelshelf`) → Public → بدون README خودکار → **Create repository**.
2. **آپلود پروژه**: در صفحه مخزن **uploading an existing file** را بزنید یا **Add file → Upload files** و **همه محتویات پوشه پروژه** (محتویات، نه خود پوشه؛ یعنی `package.json` باید در ریشه مخزن باشد) را بکشید.
   - پوشه‌های `node_modules` و `dist` را آپلود نکنید.
   - برای آپلود کل پوشه‌های تو در تو از رابط وب، همه فایل‌ها را یکجا انتخاب کنید که ساختار حفظ شود؛ اگر مرورگر پوشه‌های خالی را نپذیرفت نگران نباشید — این پروژه پوشه خالی ندارد.
   - راه‌حل جایگزین مطمئن: [GitHub Desktop](https://desktop.github.com) یا خط فرمان `git`.
3. **فعال‌کردن Pages از طریق Actions**:
   - به **Settings → Pages** بروید.
   - در بخش **Build and deployment**، گزینه **Source** را روی **GitHub Actions** بگذارید. (این مرحله حیاتی است!)
4. **اولین انتشار**: یک Commit ایجاد کنید (مثلاً ویرایش یک فایل) یا در تب **Actions** انتخاب «Deploy NovelShelf to GitHub Pages» → **Run workflow** → **Run**.
5. **پیدا کردن نشانی سایت**: پس از سبز شدن Workflow، نشانی در **Settings → Pages** (بخش "Your site is live at") دیده می‌شود:
   - مخزن عادی: `https://USERNAME.github.io/REPOSITORY/`
   - اگر نام مخزن `USERNAME.github.io` باشد: `https://USERNAME.github.io/`
   - **Base Path به‌صورت خودکار محاسبه می‌شود** و لازم نیست چیزی تنظیم کنید.
6. **تنظیم نام سایت** (اختیاری): فایل `src/config.ts` را ویرایش کنید: `SITE_NAME`، `SITE_TAGLINE`، `REPO_URL` (نشانی مخزن شما — پس از تنظیم، لینک‌های مخزن در فوتر و صفحه «درباره» فعال می‌شوند).
7. **حذف کتاب‌های نمونه** (اختیاری): دو پوشه `novels/alice-in-wonderland/` و `novels/golestan-saadi/` فقط نمونه‌اند (متن‌های مالکیت عمومی). برای حذف: پوشه در GitHub را باز → هر سه فایل را با سطل حذف → Commit.
8. **محافظت از شاخه اصلی** (اختیاری): برای تغییرات مهم می‌توانید در Settings → Branches قاعده اضافه کنید؛ اما روند عادی افزودن کتاب با Commit مستقیم روی `main` ساده و امن است، چون Workflow پیش از انتشار اعتبارسنجی می‌کند.
9. **امنیت**: این پروژه به هیچ Secret، کلید API یا توکنی نیاز ندارد و نباید داشته باشد.

## ۷. عیب‌یابی

| مشکل | علت محتمل و راه‌حل |
|---|---|
| **Workflow قرمز شد** | تب Actions → اجرای شکسته → مرحله شکسته. پیام‌های فارسی هر خطا شناسه کتاب و علت را می‌گویند. رایج‌ترین‌ها: JSON خراب در info.json، `id` نابرابر با نام پوشه، نام فایل EPUB/کاور ناهمسان با info.json |
| **سایت ۴۰۴ می‌دهد** | در Settings → Pages گزینه Source روی **GitHub Actions** هست؟ اولین Workflow اجرا و سبز شده؟ نشانی را با اسلش انتهایی باز کنید |
| **کاورها نمایش داده نمی‌شوند** | نام فایل کاور با فیلد `cover` یکی است؟ پسوند مجاز است؟ صفحه را با Ctrl+Shift+R تازه‌سازی کنید. اگر فقط یک کاور خراب است، جای آن «کاور در دسترس نیست» نمایش داده می‌شود و چیدمان به‌هم نمی‌ریزد |
| **کتاب جدید ظاهر نشد** | آیا Workflow سبز شد؟ کاتالوگ در زمان Build ساخته می‌شود؛ اگر کتاب را قبل از Commit کامل آپلود کرده‌اید، اعتبارسنج آن را حذف کرده است — گزارش Actions را بخوانید |
| **EPUB باز نمی‌شود / خطای نمایش** | فایل واقعاً ZIP سالم است؟ کتاب‌های دارای **DRM** پشتیبانی نمی‌شوند. ساختار پایه EPUB (mimetype، container، OPF) باید معتبر باشد |
| **فایل EPUB بزرگ‌تر از ۲۵MB** | رابط وب GitHub آپلود فایل بزرگ‌تر از ۲۵ مگابایت را نمی‌پذیرد. راه‌ها: (۱) فشرده‌سازی تصاویر داخل EPUB، (۲) آپلود با [GitHub Desktop](https://desktop.github.com) یا `git push` (حد مجاز فایل ۱۰۰MB)، (۳) [Git LFS](https://git-lfs.com) برای فایل‌های خیلی بزرگ. توجه: Pages سهمیه مخزن ۱ گیگابایت دارد |
| **مسیر فایل اشتباه / آیکون و فونت لود نمی‌شود** | اگر مخزن را تغییر نام دادید یا از مخزن user-site به project-site بردید، فقط یک Commit جدید کافی است — Base Path خودکار از نام مخزن محاسبه می‌شود |
| **متن کتاب فارسی است ولی چپ‌به‌راست نشان داده می‌شود** | در کتاب‌خوان، پنل تنظیمات → «جهت متن» را روی راست‌به‌چپ بگذارید؛ یا در info.json `"direction": "rtl"` |
| **سایت نسخه قدیمی را نشان می‌دهد** | کش مرورگر است: `Ctrl+Shift+R`. GitHub Pages خروجی را با کش ۱۰ دقیقه‌ای می‌فرستد؛ چند دقیقه صبر هم کافی است |
| **لینک‌های مستقیم بعد از Refresh نمی‌شکنند؟** | نمی‌شکنند — این پروژه از Hash Routing استفاده می‌کند (`#/novel/…`) که با GitHub Pages سازگار است |

## ۸. محدودیت‌ها

شفاف بگوییم چه چیزهایی در این معماری ممکن نیست:

- **اطلاعات شخصی محلی‌اند**: پیشرفت مطالعه، نشانک‌ها و تنظیمات فقط در IndexedDB مرورگر همان دستگاه ذخیره می‌شوند و **خودکار بین دستگاه‌ها همگام نمی‌شوند**. برای انتقال، از صفحه تنظیمات خروجی JSON بگیرید.
- **با پاک‌کردن داده‌های سایت در مرورگر، همه اطلاعات شخصی از بین می‌رود** (پشتیبان‌گیری جایگزین آن است).
- **سایت و مخزن عمومی‌اند**: هر کسی به فایل‌های مخزن دسترسی دارد. برای انتشار کتاب‌های دارای حق نشر که مجوز عمومی ندارند، این معماری مناسب نیست.
- **محدودیت‌های GitHub Pages**: سهمیه مخزن ~۱ گیگابایت، پهنای باند ماهانه ~۱۰۰ گیگابایت (نرم)، کش ۱۰ دقیقه‌ای، سقف آپلود وب ۲۵ مگابایت برای هر فایل.
- **بدون حساب کاربری، نظرات و همگام‌سازی ابری**: این امکانات به Backend و دیتابیس نیاز دارند و خارج از معماری استاتیک هستند.
- **DRM پشتیبانی نمی‌شود** و دورزدن آن انجام نمی‌گیرد.
- **حالت پیمایشی**: تنظیم «عرض ستون» و «حاشیه صفحه» در حالت صفحه‌بندی‌شده اعمال نمی‌شود (چون ساختار ستون‌های EPUB را خراب می‌کند) و در حالت پیمایشی، درصد پیشرفت در حد فصل به‌روز می‌شود — سازگاری بر ظاهر ترجیح داده شده است.
- **اعتبارسنجی EPUB ساختاری پایه است** (mimetype، container، OPF، spine، فهرست) و جایگزین کامل [EPUBCheck](https://www.w3.org/publishing/epubcheck/) نیست.
- **PWA/آفلاین عمداً فعال نشده** تا رفتار کش کهنه روی GitHub Pages ایجاد نشود؛ EPUB فقط هنگام مطالعه دانلود می‌شود (این خودش بخشی از بودجه عملکرد است).

## ۹. فرمان‌های پروژه و تست‌ها

```bash
npm install            # نصب وابستگی‌ها
npm run dev            # سرور توسعه (کاتالوگ را خودش می‌سازد)
npm run build          # کاتالوگ + بررسی TypeScript + ساخت خروجی dist/
npm run preview        # پیش‌نمایش محلی خروجی Build
npm run build:catalog  # فقط ساخت public/catalog.json از novels/
npm run validate:library  # اعتبارسنجی کامل کتابخانه (کد خروج ۱ در خطا)
npm test               # اجرای تست‌های Vitest
npm run make:samples   # بازسازی کتاب‌های نمونه
npm run make:fixtures  # بازسازی فایل‌های آزمون EPUB
```

### وضعیت تست‌ها (همگی اجرا و سبز شده‌اند)

- **۴۱ تست واحد/یکپارچه Vitest**: نرمال‌سازی جست‌وجوی فارسی، استخراج متادیتا و فهرست EPUB (EPUB 3/nav، EPUB 2/ncx، فارسی، بدون‌فهرست، خراب، غیرEPUB، OPF مفقود)، اعتبارسنجی کتابخانه (۱۰ سناریو)، ساخت کاتالوگ (۳ سناریوی یکپارچه)، لایه ذخیره‌سازی و Export/Import (۸ سناریو با fake-indexeddb).
- **دود-تست مرورگر واقعی (headless)**: رندر خانه، باز شدن کتاب‌خوان فارسی و انگلیسی، ناوبری، درصد پیشرفت، ذخیره/بازیابی محل مطالعه بعد از Refresh، فهرست مطالب و پرش، تم‌های مطالعه (تزریق CSS داخل iframe)، حالت پیمایشی، جست‌وجوی فارسی، فیلتر ژانر، صفحه جزئیات، پرش با پارامتر فصل، نشانک‌ها، بزرگ‌نمایی تصویر و تم روشن سایت.
- **تست‌های دستی انجام‌نشده**: بازبینی بصری روی دستگاه‌های فیزیکی متنوع و مرورگرهای سافاری iOS — رفتارها طبق استانداردهای وب پیاده‌سازی شده اما روی سخت‌افزار واقعی شما آزمایش نشده است.

## ۱۰. تصمیم‌های فنی

- **Hash Routing**: برای سازگاری کامل با GitHub Pages (بدون 404 در Refresh و لینک مستقیم) — این انتخاب عمدی است و در `[صفحه راهنما]` هم توضیح داده شده.
- **Base Path خودکار**: Workflow نام مخزن را می‌خواند و `--base` مناسب را به Build می‌دهد؛ همه مسیرهای فایل با `import.meta.env.BASE_URL` ساخته می‌شوند. هیچ مسیر مطلق سخت‌کدشده وجود ندارد.
- **کاتالوگ در Build**: `catalog.json` کامیت نمی‌شود (gitignore) و در هر Build تازه ساخته می‌شود؛ افزودن کتاب = فقط فایل‌های novels/.
- **امنیت کتاب‌خوان**: اجرای اسکریپت‌های داخل EPUB غیرفعال است (`allowScriptedContent:false` + حذف تگ‌های script در content hook)، فرم‌ها خنثی می‌شوند، لینک‌های خارجی با `noopener,noreferrer` در تب جدید باز می‌شوند و محتوای کتاب به داده‌های سایت دسترسی ندارد.
- **عملکرد**: کاورها Lazy Load با نسبت ثابت (بدون پرش چیدمان)، EPUB فقط هنگام مطالعه دریافت می‌شود (با جریان و نمایش حجم)، حداکثر ۳ کتاب در حافظه، تولید مکان‌ها برای درصد دقیق فقط برای کتاب‌های متوسط (≤۲۲۰ سند) در پس‌زمینه انجام می‌شود و منابع هنگام خروج آزاد می‌شوند.
- **ذخیره‌سازی**: کلیدهای پایدار (`bookId::volumeId::href` + CFI) — نه شماره صفحه — تا تغییر اندازه صفحه محل مطالعه را خراب نکند.
